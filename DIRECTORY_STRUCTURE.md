# Directory Structure

## Overview

All generated files are organized in the `generated/` directory with the following structure:

```
generated/
├── metadata/           # Parsed Informatica metadata (JSON)
│   ├── <mapping_name>_metadata.json
│   └── ...
├── pyspark/           # Generated PySpark ETL scripts
│   ├── <mapping_name>_etl.py
│   └── ...
├── sample_data/       # Generated sample CSV files (inputs)
│   ├── <source_name>.csv
│   └── ...
└── outputs/           # ETL execution results (outputs)
    ├── <target_name>.csv
    └── ...
```

## Directory Purposes

### `generated/metadata/`
Contains JSON files with extracted Informatica metadata including:
- Source definitions (tables, flat files)
- Target definitions
- Transformation details
- Data flow mappings
- Field-level metadata

**Generated by:** `infa_to_pyspark_parser.py`

**Example:**
```bash
uv run infa_to_pyspark_parser.py "Informatica PC Samples/wf_m_PatternForChurnData.xml"
# Creates: generated/metadata/wf_m_PatternForChurnData_metadata.json
```

### `generated/pyspark/`
Contains converted PySpark ETL scripts ready to run:
- Complete PySpark code with imports
- Source reading logic (CSV/JDBC)
- Transformation logic
- Target writing logic

**Generated by:** `generate_pyspark_code.py`

**Example:**
```bash
uv run generate_pyspark_code.py "Informatica PC Samples/wf_m_PatternForChurnData.xml"
# Creates: generated/pyspark/wf_m_PatternForChurnData_etl.py
```

### `generated/sample_data/`
Contains realistic sample CSV files for testing (INPUT data):
- One CSV per flat file source
- Realistic data based on field names and types
- Configurable row counts

**Generated by:** `generate_sample_data.py`

**Example:**
```bash
uv run python generate_sample_data.py generated/metadata/wf_m_PatternForChurnData_metadata.json 100
# Creates: generated/sample_data/churndata.csv
#          generated/sample_data/gender.csv
```

### `generated/outputs/`
Contains ETL execution results (OUTPUT data):
- Transformed and processed data
- Aggregations and analytics results
- Target files from ETL execution

**Generated by:** Running ETL scripts (`test_etl_simple.py`, `test_without_java.py`, or `run_etl.py`)

**Example:**
```bash
uv run python test_without_java.py
# Creates: generated/outputs/churn_by_gender_contract.csv
#          generated/outputs/churned_customers.csv
#          generated/outputs/transformed_sample.csv
```

## Complete Workflow Example

```bash
# Step 1: Parse Informatica XML
uv run infa_to_pyspark_parser.py "Informatica PC Samples/wf_m_PatternForChurnData.xml"
# Output: generated/metadata/wf_m_PatternForChurnData_metadata.json

# Step 2: Generate PySpark code
uv run generate_pyspark_code.py "Informatica PC Samples/wf_m_PatternForChurnData.xml"
# Output: generated/pyspark/wf_m_PatternForChurnData_etl.py

# Step 3: Generate sample data
uv run generate_sample_data.py generated/metadata/wf_m_PatternForChurnData_metadata.json 200
# Output: generated/sample_data/churndata.csv
#         generated/sample_data/gender.csv

# Step 4: Test PySpark code
spark-submit generated/pyspark/wf_m_PatternForChurnData_etl.py
```

## File Naming Conventions

### Metadata Files
- Pattern: `<xml_filename>_metadata.json`
- Example: `wf_m_PatternForChurnData_metadata.json`

### PySpark Files
- Pattern: `<xml_filename>_etl.py`
- Example: `wf_m_PatternForChurnData_etl.py`

### Sample Data Files
- Pattern: `<source_name>.csv` (lowercase)
- Example: `churndata.csv`, `gender.csv`

## Git Ignore

The `generated/` directory is included in `.gitignore` by default because:
- Files are auto-generated and can be recreated
- Sample data can be large
- Avoids cluttering version control

**To version control generated files:**
```bash
# Remove from .gitignore if needed
# Or commit specific files:
git add -f generated/pyspark/important_etl.py
```

## Custom Output Locations

You can override default locations:

```bash
# Custom metadata location
uv run infa_to_pyspark_parser.py "file.xml" custom/path/metadata.json

# Custom PySpark location
uv run generate_pyspark_code.py "file.xml" custom/path/etl.py

# Custom sample data location
uv run generate_sample_data.py metadata.json 100 custom/data/dir
```

## Cleanup

To remove all generated files:

```bash
rm -rf generated/
```

To remove specific subdirectories:

```bash
rm -rf generated/sample_data/    # Remove only sample data
rm -rf generated/pyspark/*.py     # Remove only PySpark scripts
```

## Best Practices

### 1. Keep Generated Files Separate
Don't manually edit files in `generated/` - regenerate them instead.

### 2. Version Control Strategy
- **DO commit:** Source Informatica XML files
- **DO commit:** Conversion scripts
- **DON'T commit:** Generated files (unless specifically needed)

### 3. Documentation
Document any custom modifications in a separate directory:
```
custom/
├── modified_etl.py      # Manually modified version
└── modifications.md     # Document changes
```

### 4. Testing
Use generated sample data for initial testing, then test with real data:
```bash
# Test with sample data first
spark-submit generated/pyspark/my_etl.py

# Then test with production data (update file paths)
```

### 5. Backup Important Conversions
If a conversion is production-ready, copy it out:
```bash
cp generated/pyspark/critical_etl.py production/etl/
```

## Troubleshooting

### Issue: Generated directory not created
**Solution:** Scripts auto-create directories. Check file permissions.

### Issue: Files overwritten
**Solution:** Generated files are overwritten by default. Use custom paths for important files.

### Issue: Can't find generated files
**Solution:** Check you're in the project root directory.

## Summary

The `generated/` directory provides:
- ✅ **Organized structure** for all auto-generated files
- ✅ **Clear separation** between source and generated code
- ✅ **Easy cleanup** - just delete the directory
- ✅ **Reproducible** - regenerate anytime from source XML
- ✅ **Git-friendly** - excluded by default

All scripts default to this structure for consistency and ease of use!
